# Goal 4 — Job queue + RunPod async submission worker

> Paste everything below the line into `/goal`. Assumes Goals 1–3 are done.

---

/goal Implement the job queue and the background worker that submits jobs to RunPod. Add: an authenticated `POST /jobs` (HTMX form) that validates input and inserts a `jobs` row with `status=queued` (text, language, voice_id, params_json per brief §5), then returns the updated queue fragment; a **RunPod client** (`internal/runpod/*`) that `POST`s to `https://api.runpod.ai/v2/10qdttbr4x3l9g/run` with header `Authorization: Bearer $RUNPOD_API_KEY` and body `{"input":{"text":...,"language":...,"reference_audio_base64":<base64 of the selected clone's stored reference bytes, omitted for stock voices>,"stream":false}}` (base64 inline — confirmed working in testing; the worker loads the cloned voice's stored reference bytes and base64-encodes them; confirm the exact field name against `sruckh/mossTTS-v1.5-runpod-serverless`; there is no public URL), reading the returned `{id, status:"IN_QUEUE"}`; a **background worker** (goroutine started at boot) that drains `status=queued` rows under a configurable max-in-flight limit, submits each, stores the returned RunPod `id`, and flips `status` → `submitted`/`in_progress`. Submission must be **idempotent per job** (don't double-submit) and must **never be called from a browser request** — only the worker talks to RunPod. Add a `/health` check that also probes RunPod (`/health` GET) and a minimal "enqueue succeeded, job queued" HTMX response. Scope: `internal/jobs/*` (enqueue handler), `internal/runpod/*` (client), `internal/worker/*` (submit loop), the jobs-table migration additions, the queue-row templ fragment, and config for max-in-flight + the endpoint URL. Don't touch: `DESIGN.md`, `index.html`, `.goals/`, `.outline/`, and the **completion/polling/audio-capture** logic (Goal 5) — this goal ends at "submitted to RunPod, id stored". Navigate with `codegraph_explore`/Serena; verify the RunPod `/run` request/response shape against **Context7** + `.goals/recon.md §1` (note: §1's reference delivery is now base64 inline, superseding the URL-only README reading). No host tooling. Write scratch to `.goals/`. Stop after 10 tries. Success is deterministic: (1) `POST /jobs` (authenticated, with a valid voice) → 200 and a `jobs` row with `status=queued` exists; (2) within the worker's tick, that row transitions to `submitted`/`in_progress` and its `runpod_id` is populated (non-empty); (3) the worker does not re-submit a row that already has a `runpod_id` (verify by inspecting RunPod call counts / a test double); (4) with `RUNPOD_API_KEY` unset/invalid, a queued job moves to `failed` with a recorded error instead of hanging; (5) `docker compose run --rm app go test ./...` exits 0 (use an HTTP test double for RunPod). If still failing after 10 tries, stop and report which check failed and the error.

## Notes for review
- **Browser never calls RunPod** — the central architecture rule (recon §1). Only the worker does.
- Idempotency + the invalid-key→`failed` path are the two failure modes worth pinning.
- Goal 5 consumes the stored `runpod_id` to poll for completion. This goal stops at submission.
